## 1. 개요

### 1.1 요구사항 명세(Software Requirements Statements, SRS)

소프트웨어 프로젝트의 기능 및 비기능 요구사항을 요약한 문서

#### (1) 구성요소

- **기능적 요구사항**: 시스템이 무엇을 해야 하는지 설명
  - 예시: {주체:사용자}가 {행동:로그인}할 수 있도록 해야 한다.
- **비기능적 요구사항**: 시스템이 어떻게 동작해야 하는지 설명(성능, 보안 등)
  - 예시: {주체:로그인응답}은 {조건:2초 이내} 이어야 한다.

#### (2) 작성 기준

- **명확성**: 문장의 의미가 명확하여 한 가지 의미로 해석되어야 함
- **검증 가능성**: 요구사항이 테스트 가능한 형태여야 함
- **일관성**: 다른 요구사항과 충돌되지 않아야 함
- **완전성**: 필요한 조건이 빠짐없이 포함되어야 함
- **추적 가능성**: 요구사항의 출처와 구현 위치를 추적할 수 있어야 함
  - 예시: 회의록(2025/11/15), 회사 내규(○조 ○항)

#### (3) 산출물

- **유스 케이스 다이어그램**: 시스템과 사용자 간의 상호작용을 보여줌
- **클래스 다이어그램**: 시스템 개체의 속성과 메서드를 보여줌

#### (4) 기대효과

- **수정 용이성**: 기능 변경 시 이력이 명확하며, 영향도 분석이 용이
- **추가 요구로 인한 혼선 최소화**
- **구현에 대한 근거 제공**

### 1.2 프로젝트 배경 및 목적

#### 배경

- 1인 가구 증가 및 비대면 트렌드 확산으로 홈트레이닝 시장 급성장
- 개인적 여건으로 운동량이 부족하거나 정확한 자세로 운동하기 어려운 사람들 증가
- 기존 홈트레이닝 서비스는 일방향 영상 제공에 그쳐 개인 맞춤형 피드백 부족

#### 목적

- AI 자세 인식 및 빅데이터 분석을 통한 개인 맞춤형 홈트레이닝 서비스 구축
- 생체정보 기반 운동 루틴 추천, 실시간 운동자세 교정, 커뮤니티 기능 제공
- 구독형 비즈니스 모델을 통한 지속 가능한 수익 창출 및 사용자 건강관리 경험 제공

### 1.3 시스템 환경

#### 시스템 구성

- 사용자 ↔ React 웹앱(프론트엔드) ↔ FastAPI 백엔드 ↔ 데이터베이스
- 외부 API 연동: 결제 시스템, 웨어러블 기기 데이터 수집, 지도 API

#### 개발 환경

- **프론트엔드**: React 기반 반응형 웹
- **백엔드**: FastAPI (Python) 기반 API 서버
- **AI 모델**: MediaPipe Pose, YOLOv8-Pose (자세 인식), LightGBM (운동 세트 예측)
- **데이터베이스**: PostgreSQL
- **배포**: 초기 로컬 서버, 확장 시 AWS/GCP 클라우드

#### 하드웨어 환경

- **현재 보유 자원**: PC, 모니터, 카메라
- **GPU/클라우드 서비스**: 미운용 (초기), 향후 확장 예정

| ROM (Range of Motion) | 관절 가동 범위 측정 데이터 |
| BMI (Body Mass Index) | 체질량지수 (체중/키²) |
| 기초대사량 (BMR) | 생명 유지를 위한 최소한의 에너지 소모량 |

## 참고사항

### 중요도 기준

- **상**: 필수적으로 구현되어야 서비스가 정상 작동 가능
- **중**: 사용자 경험 및 보안에 중요, 없을 경우 문제는 없지만 품질 저하
- **하**: 부가적인 편의 기능이나 향후 개선 요소로 분류 가능

### 난이도 기준

- **상**: 복잡한 알고리즘, 대용량 처리, 고급 보안/암호화 등
- **중**: 외부 API, 보안, 인증 등 포함. 중간 수준의 로직
- **하**: 단순 UI/로직 수준, 특별한 외부 API 없음

### 약어 정리

- **FR**: 기능 요구사항 (Functional Requirement)
- **NFR**: 비기능 요구사항 (Non-Functional Requirement)
- **PR**: 성능 요구사항 (Performance Requirement)
- **AR**: 가용성 요구사항 (Availability Requirement)
- **SR**: 보안 요구사항 (Security Requirement)
- **OR**: 운영 요구사항 (Operational Requirement)
